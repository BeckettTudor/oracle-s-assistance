Oracle's Assistance
Learning Quantum Search Advantage Through an Interactive Greek Myth

Oracle's Assistance is an educational, browser-based platformer that teaches the intuition and concepts behind Grover's Algorithm via an interactive Ancient Greek adventure. Players take the role of Hercules, who has been given a task to find Zeus's lightning both amongst 64 identical pots.

The seemingly strenuous task becomes easier when Hercules decides to use specially weighted coins (qubits) while consulting the Oracle of Delphi (the oracle/diffusion operators), to find the bolt within one of the 64 pots

The game lets players experiment with the algorithm interactively: choosing how many iterations to perform, observing the inversion of the probability amplitudes and the increasing of the correct amplitude, and discovering why and how the algorithm can overshoot.

Theme: Quantum Unlocked

Technologies: Qiskit, Python, JavaScript, Phaser 3, Vercel

Links: Game Link · Demo Video · External Github Repo

The Gameplay Overview

Hermes, the trickster of Olympus, has stolen Zeus's lightning bolt and hidden it inside one of 64 pots in the Temple of Apollo. Zeus gives Hercules the task of recovering the bolt as quickly as possible

There is a large climb required to get up to the temple. At first, Hercules makes the climb to begin checking the pots one by one, but each opportunity to check a pot requires an offering to the Oracle, and Hercules can only carry one offering up to the temple at a time. This strongly emphasizes the need for better search efficiency.

Platforms Up to the Temple

Hercules has another idea; he will use six magical golden coins to represent each of the 64 pots as individual binary strings, because there are 64 unique sequences of heads and tails. Instead of inspecting each location individually, he can have the Oracle give him a blessing to change the coins weightings, increasing the likelihood of coin toss pointing him to the correct pot.

Hercules' Coins

Coin Probability Amplitudes on the Oracle's Scroll

However, each time Hercules receives a blessing, he must also return back down to obtain another offering, and if he takes too many blessings, his chances of success on the coin toss will actually begin to come back down, and so he must use the Oracle's help to find the optimal number of blessings.

Additionally, whenever he throws the coins, the blessings are expended and they return back to their fair, 50/50 status. Therefore, throwing (measuring) only after the optimal number of blessings is absolutely necessary to minimize the number of trips.

Measurement

After the desired number of iterations, the state is measured in the computational basis. The state collapses according to the probability amplitudes of each basis state, and the correct outcome is achieved with high probability. In-game, Hercules will toss his coins, expend all the blessings, and smash the pot the coins tell him to smash.

Our Quantum Implementation

The project includes a corresponding six-qubit Qiskit implementation of Grover's algorithm hosted on Qollab, alongside the independently runnable browser-based game. The game utilizes its own backend simulator with randomly generated outcomes according to the probabilities.

The quantum implementation consists of:

Target selection: A six-bit state is selected as the search target and remains unchanged for the duration of a single experiment.
State preparation: Hadamard gates prepare a uniform superposition across all 64 possible states.
Phase oracle: A marked-state phase operation distinguishes the target from the unmarked states.
Diffusion operator: A reflection about the uniform superposition amplifies the marked state's amplitude.
Measurement: The final circuit is measured to estimate the probability distribution across all 64 possible outcomes.
Ideal Simulation Versus Quantum-Backend Execution

The browser game uses its own ideal simulation of the six-qubit search to provide immediate feedback and visualizations during gameplay, while the Qollab implementation executes Qiskit circuits using a simulator selected by the user. This allows the quantum search to be examined and experimented with independently of the game's presentation.

The ideal probability predictions do not factor in noise, just computer-random based variations. The very slight differences can potentially be observed between the game and the pure algorithm on real quantum hardware, especially for larger, deeper, multi-qubit circuits.

Additionally, the project compares oracle queries with traditional search function queries to gauge the difference in time complexity. This comparison is not perfect, with each type of query consuming different amounts of computing time and power, and other computing time from the individual circuits needing to be accounted for. However, the comparison serves as a relatively accurate estimate, especially as search spaces get larger.

Running the Qiskit Implementation on Qollab
Open the Code tab of this Qollab project.
Select Run Project.
Choose any simulator or actual hardware.
Configure the marked state, number of Grover iterations, and number of measurement shots using the available run parameters.
Execute the circuit and examine the resulting measurement counts and probabilities.
Repeat the experiment with different iteration counts and compare the outcomes with the theoretical probability curve.

For the clearest comparison, keep the marked state and shot count constant across runs while varying the number of Grover iterations.

The experiment is designed to be reproducible for any marked state from 000000 through 111111, and it is suggested to experiment with any series of iterations, from:

None: Uniform distribution of outcomes
Limited: Higher probability of successful state selection (although not highest)
Optimal: Initial maximum of the successful state selection probability
Overshot: Reduced probability of successful state selection (can be reduced anywhere from minimally, to back to uniform, to below uniform)
What Makes This an Educational Contribution?

Oracle's Assistance aims to connect abstract quantum concepts with decisions and actions that a player can understand intuitively and interact with actively. Its educational contribution is built around three ideas:

Learning by consequence. The impact of the iterations is well explained, and the optimal number is given, but not enforced. This means players can experiment with the number of iterations, and observe the consequences. They can also play many times and observe the potential for an outcome to be incorrect, despite a higher likelihood than not for it to be the correct one.

Making interference and phase shifting properties tangible. The game doesn't present quantum computing as some nebulous ability to test every answer simultaneously. Instead, the game focuses on how the phase changes and interference create a marked shift in probabilities, and how this shift increases with each iteration.

Teaching both the limitations and the advantages. Players interact with the nature of probabilistic measurement, the tradeoff between additional queries and success probability, and the surprising fact that the iterations can overshoot and success chance can be lowered.

The intended audience is those curious about quantum, who are comfortable with basic probability and binary numbers, but have little or no previous quantum-computing experience.

Of the algorithms with a proven quantum advantage, Grover's is, to us, the simplest to begin teaching with. Those who are completely new to the field will get a good introduction to the potential of quantum advantage, and a good intuition of how this technology can potentially provide advantages over classical methods.

Limitations and Future Development

The current six-qubit, 64-outcome search space problem is deliberately small enough to visualize and simulate efficiently. This makes it useful for education, but not as a demonstration of practical computational advantage.

Potential extensions include introducing multiple marked states, adding in an element of quantum noise to deal with, adding different search-space sizes, and potentially allowing players to construct their own oracles.
